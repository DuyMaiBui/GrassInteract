# GPUGrass

A **standalone** interactive grass plugin for Unity built-in **Terrain** — independent of WorldPainter.
Reads a Terrain's painted detail (grass) layer, renders it as GPU-instanced interactive grass with wind +
bend (point & trail interactors), scales across devices (down to OpenGL ES 3.0), and sets up in one click.

- Engine: Unity 6 (6000.3.x), URP 17.3.
- Source of truth: the Terrain's detail/grass layer (paint with **Terrain ▸ Paint Details**).
- The Terrain renders the ground; its own detail rendering is disabled; GPUGrass renders the grass.

## Status — built in passes

This module is extracted + decoupled from the proven WorldPainter `GrassInteract` system.

### ✅ Pass 1 — foundation (this commit)
- `Runtime/GpuGrassTierProbe.cs` — GPU-indirect vs CPU-instanced device probe (GLES3.0 → CPU).
- `Runtime/Interact/GrassInteractor.cs`, `GrassTrailInteractor.cs` — point + trail disturbances (registry,
  folded params; no companion component).
- `Runtime/GpuGrassConfig.cs` — all tunables (density, LOD, wind, bend, trail, tier) as one ScriptableObject.
- `Runtime/GpuGrassBakeData.cs` — editor-baked placement asset (the chosen editor-bake source).
- `Runtime/IGpuGrassRenderer.cs` — render-tier seam.
- `Runtime/GpuGrassController.cs` — the one component; picks the tier + drives sim/draw (edit + play).
- `Editor/GpuGrassAutoSetup.cs` — **Tools ▸ GPUGrass ▸ Auto-Setup Grass On Terrain**: adds the controller,
  creates + wires config + bake assets, disables terrain detail rendering. Zero manual setup.

### ✅ Pass 2 — render core + bake (this commit)
- `Editor/GpuGrassBaker.cs` — Terrain detail layers (`GetDetailLayer`) + height/normal/slope →
  `GpuGrassBakeData` (deterministic rejection sampling at `targetDensityPerSqM` weighted by painted
  coverage, ground-snap via `SampleHeight`, slope mask via `GetInterpolatedNormal`).
- `Runtime/Render/GpuGrassRenderer.cs` — **GPU indirect tier only** (compute cull + `RenderMeshIndirect`),
  extracted from `GrassGpuEngine` with WorldPainter deps stripped (WpLog→Debug; dropped
  WorldRootBinder/ScatterLayer/GrassScatter/density-controller/scale-factor).
- `Runtime/Render/GpuGrassChunkedBuffer.cs` — standalone counting-sort chunk partition + GPU buffers,
  built from the `GpuGrassBakeData` parallel arrays (no `GrassScatterResult` dependency).
- `Runtime/Sim/GpuGrassInteractorBuffer.cs` + `GpuGrassTrailBuffer.cs` — per-frame GPU upload of the
  point + trail interactor registries (wind + bend are evaluated GPU-side; the CPU only advances time).
- `Shaders/GpuGrassIndirect.shader` (target 4.5) + `GrassCull.compute` + `GpuGrassSpace.hlsl` (identity
  space helpers replacing WorldPainter's `WorldRootTransform.hlsl` — terrain grass is world-space).
- `Runtime/Render/GpuGrassRenderBootstrap.cs` — wires `GpuGrassController.RendererFactory` automatically
  (play + edit), constructing the GPU tier from the config's serialized compute/shader/material refs.
- Setup wires the render assets and runs the bake. (The LOD blade mesh is assigned manually on the shared
  config as of Pass 3 — it is no longer auto-generated; see Pass 3.)

> **No CPU grass renderer.** Per the tier policy, non-compute devices fall back to Unity's built-in Terrain
> detail grass (the controller re-enables `detailObjectDistance` on that tier), and low-end devices get no
> grass — so there is no custom `RenderMeshInstanced` grass tier to build.

### ✅ Pass 3 — scene window + multi-terrain + Hi-Z occlusion
- **Single entry point:** the standalone **Tools ▸ GPUGrass ▸ Auto-Setup Grass On Terrain** menu item is
  **removed**. Everything is now driven from one editor window: **Tools ▸ GPUGrass ▸ Scene Grass Setup**
  (`Editor/GpuGrassSceneWindow.cs`). `GpuGrassAutoSetup.SetupOnTerrain(terrain, sharedConfig)` survives as a
  callable helper (config is now injected, not self-created).
- **UIToolkit window** (`Editor/GpuGrassSceneWindow.cs`, built with `CreateGUI`/`rootVisualElement` like the
  WorldPainter editor): authors a single scene `GpuGrassConfig` via an embedded `InspectorElement` (edit grass
  properties once), and `GpuGrassSceneSetup.SetupScene` applies it to **every active Terrain** in the scene —
  each terrain keeps its own hidden `GpuGrassBakeData`. The window shows a read-only per-terrain status list
  (name · blade count · tier); the baked placement arrays are not shown.
- **Manual LOD mesh, shared by all terrains:** the blade mesh is **no longer auto-generated** — assign it on
  the shared config (LOD / Render ▸ Lod Meshes) so every terrain renders with the SAME mesh. The window shows
  a warning until a mesh is assigned; baking still runs, but nothing renders until the mesh is set.
- **Bake data is locked:** `GpuGrassBakeData` has a read-only custom inspector
  (`Editor/GpuGrassBakeDataEditor.cs`) — it shows a summary (blade count, bounds, source) and hides the raw
  placement arrays, so the generated data can't be hand-edited (re-bake to change it).
- **Per-scene assets (like baked lighting):** the shared config, per-terrain bakes, and the grass material
  are written to `<sceneDir>/<SceneName>/` next to the scene file (the same place Unity stores baked
  lighting). The config is named `<SceneName>_GpuGrassConfig`. Unsaved scenes fall back to
  `Assets/GPUGrass/Generated/`.
- **Auto render-asset wiring (incl. shader self-heal):** setup auto-assigns the GrassCull compute, the
  `GPUGrass/IndirectGrass` shader, and a material. The indirect renderer REQUIRES that shader — if the
  config's material is missing or on the wrong shader (e.g. URP/Lit), setup creates a correct indirect
  material (otherwise the grass silently renders nothing).
- **Optimize section** — curated perf controls (occlusion, adaptive density, LOD/cull distances, tier) bound
  to the same config (SSOT), plus *Re-apply & Rebuild* and *Apply Mobile Preset*.
- **Hi-Z occlusion culling** (`enableOcclusionCulling`, default on; fail-open): `Runtime/Render/GpuGrassHiZ.cs`
  + `GpuGrassHiZFeature.cs` (URP RenderGraph ScriptableRendererFeature) build a per-camera depth pyramid
  (`Shaders/HiZBuild.compute`, conservative max-Z) after opaques; `GrassCull.compute` ChunkCull tests each
  chunk AABB against it (prev-frame depth, reprojected). Hidden chunks are skipped before the blade cull.
  When no depth texture is available it fails open to frustum+distance culling.

> **Enable occlusion:** add **GpuGrassHiZFeature** to your URP Renderer asset (Renderer Features list),
> assign `Shaders/HiZBuild.compute` to its field, and ensure **Depth Texture** is enabled on the URP
> Renderer. Without the feature, `enableOcclusionCulling` simply no-ops (frustum+distance cull only).

## Quick start
1. Add one or more Unity Terrains; optionally paint grass with **Terrain ▸ Paint Details** (or set the config
   `PlacementSource = TerrainSurface` to scatter over the whole surface — no painting needed).
2. **Tools ▸ GPUGrass ▸ Scene Grass Setup** → pick/create the shared config → **Setup & Bake All Terrains**.
3. (Optional) For occlusion, add **GpuGrassHiZFeature** to your URP Renderer asset (see note above).
4. Attach a `GrassInteractor` (and/or `GrassTrailInteractor`) to your car/player. Done.

…or copy `Samples~/InteractiveGrassDemo/` into `Assets/` and run **Tools ▸ GPUGrass ▸ Build Demo Scene**
for a ready-made example.

## Design notes
- **No WorldPainter dependency** — this module ships on its own.
- **Editor-bake** (not runtime-read): grass placement is baked to `GpuGrassBakeData` so mobile pays no
  runtime `GetDetailLayer`/scatter cost. Re-run auto-setup after repainting.
- **Tier policy (one probe, three outcomes):** compute-capable → interactive GPUGrass (terrain grass off);
  no compute → Unity's built-in Terrain detail grass (optional, `enableTerrainFallback`); low-end (below
  `lowEndMemoryThresholdMB`) → no grass. The controller toggles `Terrain.detailObjectDistance` to match.
- Built-in Terrain Grass/Billboard detail modes can't take a custom interactive shader — so GPUGrass uses
  the Terrain only as the placement source and renders the interactive grass itself.
