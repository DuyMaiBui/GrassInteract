# Brainstorm — Grass "lean-away" trample deform (reference-informed upgrade)

Date: 2026-06-02 · Skill: /t1k-brainstorm · Project: GrassInteract (URP 17.3, Unity 6, Mono)
Reference repo synced: https://github.com/AlexMerzlikin/Unity-GrassShader → `C:/Works/Unity/The1/_ref_AlexGrass`

## Problem statement

Grass bending "still doesn't work." After a clean editor restart (which cleared the
`Library/ShaderCache.db` lock that last session blamed), grass still shows **zero visible
bend**. So the stale-shader-include-cache theory is **disproven** — this is a real
logic/visibility gap, not a cache artifact.

User brought in AlexMerzlikin/Unity-GrassShader as a known-working reference to investigate
and upgrade the current shader/code.

## Reference vs current — architectural comparison

| | Reference (AlexMerzlikin/Roystan) | Current (GrassInteract) |
|---|---|---|
| Pipeline | Built-in RP, Unity 2021 (`ForwardBase`, `UnityCG.cginc`) | URP 17.3, Unity 6 |
| Blades | Generated by **geometry + tessellation** shader from a ground mesh | **GPU-instanced** per-blade meshes, CPU chunk-cull + LOD |
| Interactors | **One** global `_Trample` vector4 (pos.xyz + radius.w), `material.SetVector` | **Many** — top-down trample RenderTexture (RHalf), sampled per-vertex |
| Bend | **Lean horizontally away** from trample point, `1 − saturate(dist/radius)` falloff, progressive per segment → curved lean | **Collapse height straight down + random hashed splay** |
| Target | Desktop | **Mobile** (10k–50k blades) — hard requirement |

### Why no wholesale port
- Geometry/tessellation shaders **don't run on most mobile GPUs** and are effectively
  deprecated in URP → a port kills the mobile goal.
- Reference supports a single interactor; current needs N.
- Built-in RP ≠ URP.

### What's worth borrowing
The reference's **lean-away** bend is dramatically visible (see `Interaction.gif`), whereas the
current **height-collapse** is subtle on a thin cross-quad viewed at a shallow angle — easy to
mistake for "not working." Adopting lean-away both improves the look AND makes the deform far
easier to verify.

## Decisions locked (via AskUserQuestion)

1. Current state: **restarted, still nothing** → real gap, not cache.
2. Reference = **correctness oracle**; keep URP + instanced + RT + mobile architecture.
3. Bend look = **lean away from interactor**.
4. Mobile = **mandatory** (instanced + URP only, no geometry/tessellation).
5. Direction source = **gradient of the scalar trample map** (Option A).

## Recommended solution

### Core idea — derive bend DIRECTION from the trample map's gradient
The reference needs a push direction (`normalize(blade − tramplePoint)`); the current
`_GrassTrampleMap` is scalar (intensity only). Each interactor splats a radial bump, so the
**negative gradient of the intensity field points away from any hot region** — the natural
generalization of the reference's single-vector push to N interactors, **with no RT or C#
change**.

```hlsl
intensity = SAMPLE(_GrassTrampleMap, uv).r                 // as today
// NEW: 4-tap central-difference gradient; push points away from hot
float2 push = -gradient(_GrassTrampleMap, uv);
push = (length(push) > 1e-4) ? normalize(push) : 0;
posWS.xz += push * intensity * heightT * _BendStrength;     // lean: tip moves most, root planted
posWS.y  -= vertical * intensity * heightT * _FlattenAmount;// optional slight height loss
```
`heightT` weighting anchors the root and moves the tip most → the curved lean from the
reference gif. Applied identically across forward / shadow / depth passes so silhouettes match.

Fallback (only if gradient proves noisy): **Option B** — direction-encoding RGHalf RT storing
XZ push + intensity; exact direction, single tap, but 2× RT memory and a splat/averaging
rewrite.

### Evaluated approaches

- **A. Gradient of scalar map (CHOSEN)** — reuse RHalf RT, +4 taps/vertex, N interactors free,
  zero C# change. Degenerate (zero) gradient exactly at a hot peak, where push magnitude ≈0
  anyway → acceptable.
- **B. Direction-encoding RT** — exact, single tap; heavier memory + splat rewrite + vector
  averaging across overlapping interactors. Held as fallback.
- **C. Port reference geometry/tessellation grass** — rejected: breaks mobile + URP, discards
  the instanced pipeline.

## Implementation considerations & risks

- **Phase 0 (verification-first):** add a `_GRASS_DEBUG` keyword that outputs the sampled
  trample as color; confirm on the *current post-restart* editor whether the sample is hot
  **through the include**, and re-run the inline-vs-include A/B last session flagged. This
  pins down whether "still nothing" is data-path, include-mechanism, or just-too-subtle —
  before writing new math. (`read_console` is unreliable on this bridge for runtime logs — use
  `execute_code` return values + GPU `ReadPixels`, and a shader-debug-viz, per prior gotchas.)
- **Phase 1 (lean-away deform), delivered cache-safe:** last session proved "inline folds,
  include doesn't" and a restart didn't fix it. Phase 1 ships the deform in a form that cannot
  be defeated by the include-cache class — decided by Phase 0 evidence: either a single include
  proven to recompile, or inlined-with-SSOT-comment into the 3 passes if the include mechanism
  is confirmed unreliable (correctness > DRY, documented inline).
- **Mobile cost:** 4 gradient taps/vertex × up to 50k blades. Taps hit a small RT (cheap,
  cache-friendly). Profile via `rendering_stats`; if hot, drop to a 2-tap forward difference or
  precompute gradient into the splat (→ Option B).
- **SRP batcher / loose globals:** `_GrassFieldRect`, `_GrassWind*` are loose globals set via
  `Shader.SetGlobalX` — must stay OUTSIDE `UnityPerMaterial`. Verify this didn't silently break
  the deform path.
- **Three passes must stay in lockstep** — forward/shadow/depth all apply the identical deform
  or shadows/depth desync from the visible blade.

## Success metrics / validation
- Debug keyword shows the trample sample hot under a moving interactor (data path proven).
- A moving `GrassInteractor` produces a **visible lateral lean** trailing it (not just a faint
  squash), recovering after it passes.
- Forward + shadow + depth silhouettes agree.
- `rendering_stats`: no material FPS regression vs current at the demo's instance count.
- Zero per-frame GC; no new compile warnings.
